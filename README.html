Monash Sport Performance Dashboard

An interactive R Shiny application built with Monash Sport for the ETC5543 Business Analytics Creative Activity. It brings financial and operational Excel reports into a consistent dashboard and provides forecasting and pricing-planning tools.

Open the live dashboard · User guide · Developer maintainer guide

Project team: Ayush Pandia and Ziqi Feng
Monash Sport mentors: Alicia Stack and Darren McLeod
Academic mentor: Minh Huynh (Monash University)

The deployed application uses Shinylive, so R runs in the user’s browser. Uploaded reports are processed locally in that browser session; the published site does not receive or store report data. Monash Sport’s confidential source workbooks are not included in this repository.

Dashboard features

Page What it provides Source reports
Executive Dashboard Three fixed presentation-ready sections: Overview (financial KPIs, four charts, summary and insights), Site (visits, memberships, growth, site finances and rankings) and Venues (attendance, facility hire, casual wages, merchandise/equipment revenue and insights). Includes Year Review, two-year Comparison, chart hover readouts and full-screen Presentation View. Monthly Site, Detailed Site and Venues Tracking reports, depending on section
Overview Organisation-wide income, expenses, budget variance and revenue performance Monthly Site Reports
Site Comparison Site-level financial comparisons and facility breakdowns Monthly Site and Detailed Site Reports
Site Detail Visits, membership and enrolment measures for an individual reporting unit Detailed Site Reports
Venues Operations Attendance, facility/court hire, memberships, online sales, merchandise, finance and casual workforce Venues Tracking Reports

The three Executive sections use fixed charts, not the old Choose Visuals workflow. Detailed pages retain their own filters. Missing reported months or years remain gaps rather than being treated as zero; supported charts show exact values on hover. For design decisions see Dashboard design.

Quick start

GitHub repository: Monash Sport Performance Dashboard

Use the live application: Open the dashboard, go to Data, and upload supported workbooks. To try it without confidential reports, use the synthetic workbooks in data/sample/.

Run locally: Install R 4.4 (the project was built with R 4.4.3) and RStudio. Clone/download the repository and run from its root:

renv::restore()
shiny::runApp()

The package versions are recorded in renv.lock. For the full import and upload workflow, file naming, warnings, saved-data format and templates, see Maintainer guide: data upload and the user guide.

Data sources and privacy

The application supports three report families:

Report family Main outputs
Monthly Site Reports Income, expenses, budgets, discounts and revenue reconciliations
Detailed Site / Business Unit Reports Site finance, Direct/Indirect visits, memberships and enrolments
Venues Tracking Reports Attendance, hire revenue and transactions, workforce hours/wages, online sales and merchandise/equipment measures

Uploads are validated before being used in charts. Imported records retain source-file, worksheet and cell-position metadata to help reconcile figures. The data dictionary defines the cleaned tables; Excel templates document required workbook layouts.

The workbooks under data/sample/ use artificial figures and must never be treated as actual Monash Sport results. Don’t commit original reports, exported confidential .rds files or screenshots containing real values. The live app does not keep uploads between sessions; Save current data produces a local .rds file that must be handled as confidential data.

Maintaining the application

This repository is designed for an incoming Monash Sport developer to take over. Start with docs/maintainer_guide.md before changing data aggregation rules or source templates.

If you need to… Where to start
Upload the next reporting year New reporting years (normally no code change)
Support a changed Excel template Importer maintenance steps
Add a site, facility or new measure Adding reporting categories
Change a KPI, plot or hover readout Dashboard change procedure
Change the forecast Forecast maintenance
Diagnose incorrect totals Calculation safeguards
Release an update Troubleshooting and release checklist

The most important safeguards are to distinguish unreported data from zero, avoid summing YTD totals together with their monthly/detail components, and avoid summing successive membership snapshots. A wage budget difference must use a clearly stated sign convention. More detail and exceptions are in the maintainer guide.

Testing and deployment

Run the basic regression suite from the project root:

source("tests/run_tests.R")

Run the synthetic-workbook end-to-end checks before releasing:

source("tests/run_sample_tests.R")

For sequential debugging, first run Sys.setenv(MONASH_SPORT_TEST_WORKERS = "1"). Authorised maintainers can use tests/run_full_tests.R with the confidential workbooks kept on their own computer, never in the repository. See Testing instructions for expected coverage and how to update intentional snapshot changes.

GitHub Actions tests and builds the Shinylive site; the deployment workflow publishes changes from main to GitHub Pages. Review the code diff, run tests, and check the deployed application with synthetic reports. See the deployment guide.
